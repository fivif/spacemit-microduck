# 01 · K3 版运行时软件栈 — 总体架构

> 目标:**由 SpacemiT K3 承担 Microduck 的大脑**。运行时(主仓 `microduck/` 的
> Rust daemon 集)在 K3 上原生编译运行;仿真/训练不进 K3。

## 分层

```
┌───────────────────────── 机器人大脑(不动代码,换主体) ────────────────────────┐
│  robotd ──50Hz── duck-control(obs 61D → ONNX 策略 → safety → 舵机目标)      │
│     │                                 │ ort[load-dynamic] → libonnxruntime.so │
│     ├── robotd-params(robotd.toml)     └─ Dinamixel UART 1Mbps /dev/ttyS*     │
│     ├── duck-ipc-proto(JSON-RPC socket)                                        │
│     ├── updaterd(签名更新) · configd(wifi/身份) · tofd(头部 ToF) · padd(手柄)   │
│     └── btd(BLE 门) ── [K3 无 BLE 板载 → 依硬件定,可裁剪]                        │
├───────────────────────── 换脑前后差异 ---------------------------
│  裁掉: mediad(camera/mic/WebRTC;K3 未做)                                       │
│  保留: duck-detect(rknn / SpaceMIT EP / CPU 三选一,全走 dlopen)                 │
│  保留: pet-detect —— 纯 Rust(rustfft 出 log-mel),推理走 ort dlopen,不是 rknn    │
│  新增: K3 板级 UART 引脚定义 ↔ 舵机总线 | systemd unit | Bianbu 包              │
└───────────────────────────────────────────────────────────────────────────────┘
```

## 组件矩阵(主仓 crate × K3 决策)

| crate | 依赖(实测 `Cargo.toml`) | K3 决策 | 理由 |
|---|---|---|---|
| robotd | 纯 Rust + duck-control |  保留 | 主控环 |
| duck-control | `ort` load-dynamic、serialport(无 libudev)、libloading |  保留 | **ONNX 靠 dlopen,K3 现成 Runtime** |
| duck-ipc-proto / robotd-params / kinematics / odometry / sounds / xtask / test-support | 纯 Rust |  保留 | |
| updater / robotctl / duckctl | 纯 Rust(minisign/tar/zstd/sha2) |  保留 | 恢复路径工具 |
| configd / btd | dbus 0.9 **vendored** |  可编译(BLE/NetworkManager 设备看硬件) | 平台无关 |
| padd / tofd | 纯 Rust |  保留(v4l2/I²C 是标准接口) | tofd 的 VL53 是 HAT,I²C 板级待验 |
| mediad | **gstreamer-sys 链(v1_22)** |  **排除** | K3 尚未把这条链跑起来,不是 riscv64 缺实现(见 [`../../docs/K1-MEDIA.md`](../../docs/K1-MEDIA.md)) |
| duck-detect | `dlopen`(rknn / SpaceMIT EP / CPU 三选一) |  保留 | 三条运行时都是 `dlopen`,编译期不需要任何厂商库;运行期有 NPU 用 NPU、没有退回 CPU(见 `duck-detect/src/spacemit.rs`)。`duck-bench` 也在这个 crate 里 —— 它是板上唯一能把三条路分别测一遍的工具 |
| pet-detect | `ort` load-dynamic、rustfft、hound |  保留 | 纯 Rust 的音频分类器(听摸头声),模型 20 KB。**与 rknn 无关** —— 它和 robotd 走同一条 ORT dlopen 路径,K1 上实测编译 2m46s、跑得通(见 K1 `docs/05`) |

## 换脑后的硬件差异核对表

| 硬件件 | 原核心板 | K3(Pico-ITX) | 待办 |
|---|---|---|---|
| 舵机总线 | /dev/ttyS2, 1Mbps | UART x15(板级引出有限) | P1 定引脚 + dts 核对 |
| IMU | 总线 id 200(与舵机同线) | 同上(总线协议,与 CPU 板无关) |  无额外事 |
| 摄像头/麦克风 | 板载/USB | 无采集(可 USB) | mediad 不在 K3 → 取帧要另接;检测器本身已可跑(见下行) |
| NPU | rknn(duck-detect) | SpaceMIT EP(onnxruntime 的推理 EP) | 检测器已接 EP 并在 K1 上验证(同图快 5.1×);**K3 上未实测** |
| BLE | 板载(duckctl/手机控制) | Pico-ITX 无板载 BLE(待确认) | 若需手机控制:USB dongle 或 WiFi+REST |
| 供电/功耗 | 3.3/5V, ~2-3W | 5V, Pico-ITX 功耗 ~5-10W(8 核 2.4GHz) | **真机集成的最大不确定点**,P2 评估 |
| 尺寸 | ~46×22mm | 100×72mm(2.5") | 机器人外壳空间,P2 评估 |
| systemd | Armbian | Bianbu(Ubuntu 衍生) | unit 文件微调(挂载点/PATH) |
