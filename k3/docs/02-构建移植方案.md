# 02 · 构建移植方案(K3)

> 结论先行:`riscv64gc` 全原生构建,唯一裁剪 `mediad`;ONNX 走 load-dynamic 直接吃
> K3 已装的 `onnxruntime 1.24.2+spacemit.a1`。

## 1. 工具链选择:原生编译(不交叉)

| 选择 | 理由 |
|---|---|
| **在 K3 上 rustup + cargo build**(采纳) | 单一 glibc 2.43 平台、8×X100 2.4GHz(首编 ~15-20 min 可接受,增量秒级);没有交叉 link 环境(riscv64-linux-gnu-gcc)要维护;crate 在 K3 上直接落地可测 |
| 交叉编译(zigbuild `riscv64gc-unknown-linux-gnu`)+ scp | 备选。若 K1/量产板多台时再上(与现有 `aarch64 ... 2.31` zigbuild 同款思路;注意 riscv glibc 版本匹配) |

- Rust target:`riscv64gc-unknown-linux-gnu`(稳定 tier2,rustup 自带)。主仓 edition 2024 / rustc ≥1.89 → 安装 stable(≥1.89,2026-09 当前 1.9x )。
- 前提:无 C 编译依赖(mediad 除外)——唯一带 C 的是 `dbus vendored`(自编 libdbus,纯 C 编译,已过 gcc;有 build.rs gcc 即可 )。

## 2. 依赖审计结论(2026-09-08 实测 `Cargo.toml`)

| crate | 关键依赖 | 审计结论 |
|---|---|---|
| robotd/duck-ipc-proto/robotd-params/kinematics/odometry/updater/robotctl/sounds/xtask | 纯 Rust | |
| duck-control | `ort =2.0.0-rc.11 {load-dynamic}`、`serialport {default-features=false}`、`libloading` |  ort 通过 dlopen 加载 libonnxruntime;**不编译 C++** |
| configd/btd | `dbus 0.9 vendored`(自编 libdbus) | (无 libudev/sdl 等) |
| padd/tofd | 纯 Rust | (tofd 使用标准 I²C 驱动,*板级通断待验*) |
| duck-detect/pet-detect | libloading 0.9(rknn .so dlopen) | 注意: 可编译,rknn 库缺失时**运行时**不可用 |
| **mediad** | gstreamer-sys 链(gstreamer/gstreamer-app/webrtc/video 0.24,features v1_22) |  **排除**(`--exclude mediad`)——K3 无 mpp/硬件编码/GStreamer 适配 |

**构建命令**:
```bash
cargo build --release --workspace \
    --exclude mediad \
    --exclude duck-detect --exclude pet-detect   # 可选:无 NPU 无摄像头,一并裁;要"编译全绿"就只裁 mediad
```

## 3. ONNX 对接(关键路径,与真机同构)

- `duck-control/policy.rs::ensure_runtime` 用 `libloading` 预探 `libonnxruntime.so`
  (K3 已有:`dpkg -l | grep onnxruntime → 1.24.2+spacemit.a1`,位置 /usr/lib)≥ 地板 1.23 。
- `ort` setup_api 兼容性(rc.11 绑定 vs spacemit 定制 build):**P0 必测项** ——
  跑 `robotd --sim` 前,先用 C 或 Rust 小探针 `ort` 初始化 + 加载一张策略 ONNX。
- **EP(60TOPS)接入**:spacemit EP 是定制 ORT build 内嵌(libspacemit_ep.so.2),非标准 runtime-config EP;
  robotd 侧 FFM 只认标准 ORT **CPU EP**。→ **第一版走 CPU**(策略 MLP ~30 万参数,
  50Hz 下 CPU 负担 <5%),EP 加速是后续优化(需 custom EP 注入)。
- 策略二进制:官方集 `pollen-robotics/microduck-policies`(manifest schema2,`robotctl policy load`);

## 4. 总线与系统集成

- **舵机总线**:Dynamixel Protocol v2 @1Mbps,`TIOCEXCL`+flock;K3 15×UART 中选一路(P1 用 板级引脚表核对,优先 `uart0/2` 通用区;注意 1.8V/3.3V 电平 —— Pico-ITX GPIO 电压需查)。
- **systemd unit**:K3 上重写 robotd/configd/updaterd/tofd/padd 单元(参考主仓 `deploy/`);
  关键项:`/run/robotd.sock`、`robotctl configure` 的 `/etc/robot/*.toml`、日志 journald。
- **型号对接**:`robotd-params` 的 `ROBOT={model,hw_rev,servos:xl330}` 元数据不涉及 CPU 板,无需改。

## 5. 风险清单(P0→P2)

| # | 风险 | 概率 | 对策 |
|---|---|---|---|
| R1 | `ort rc.11 setup_api` 与 spacemit 定制 ORT 1.24.2 不兼容(panics) | 中 | P0 先做探针;对策兜底:apt 空间mit 的 ORT 也提供标准 `libonnxruntime`?否则需要(在 K3 上)一个自装标准 ORT wheel 或降低绑定版本 |
| R2 | dbus vendored 在 riscv 编译问题 | 低 | gcc 15 有;若失败同样 --exclude btd/configd(控制环不依赖它们) |
| R3 | 板级 UART 不可用/引脚没有 | 低-中 | 换 UART 口;或 USB-serial 桥(Ctrl+U);或 K3-CoM260 载板(260pin 更健康) |
| R4 | 供电/功耗/尺寸不适合真机 | 中 | P2 真机评估;备选:K1 或 CoM260 更小平台(见 04) |
| R5 | 50Hz 抖动(非 RT 内核 Bianbu) | 低 | 与原平台完全同构(tokio interval Skip);8×X100 预算富余 |

## 6. 构建命令速查

```bash
# P0 一次性:
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
cd /opt/microduck-k3 && git clone --depth 1 https://github.com/pollen-robotics/microduck.git
source ~/.cargo/env && cargo build --release --workspace --exclude mediad \n
# 验证:
./target/release/robotd --help
./target/release/duckctl --help
```
