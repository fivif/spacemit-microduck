# 06 · P1 联调实录:K3 大脑驱动 MuJoCo 鸭(2026-09-08)

> **一句话**:K3(RISC-V)上原生编译的 `robotd`,通过移植的 `--sim` 客户端经 SSH 反向隧道,
> 用**官方 ONNX 策略**(spacemit ONNX Runtime)驱动本地 Windows 上的 MuJoCo 鸭 ——
> 从坐姿起身、站立、行走 1.45 m,全程未摔倒。

## 拓扑

```
┌─ K3 (<board-ip>, riscv64) ─────────────┐        ┌─ Windows (<dev-host>, x86_64) ─┐
│ robotd (本仓 v0.11.0 + sim 移植)         │        │ duck-body (MuJoCo, scene.xml)  │
│   50Hz 控制环 / 安全 / 策略热插拔         │        │   + MuJoCo viewer 窗口          │
│   ort(load-dynamic) → libonnxruntime     │        │   实时步进 (200Hz 物理/50Hz 控制)│
│   官方策略 9 个 ONNX(schema-2 manifest)  │        │                                 │
│        │                                  │        │                                 │
│        └── 127.0.0.1:7801 ──[SSH -R 反向隧道]──────┴─ 127.0.0.1:7801                 │
└──────────────────────────────────────────┘        └─────────────────────────────────┘
```

## 实测序列(观测来自仿真侧 `trunk` 字段)

| 阶段 | 操作 | 结果 |
|---|---|---|
| 启动 | `robotd --sim 127.0.0.1:7801` | `simulated body ... protocol=1`;`seated boot detected — will stand up via the sitstand policy deviation=0.33` |
| 使能 | `robot.enable {on:true}` | `driving=true` |
| 起身 | `robot.init` | `robot.init: seated boot — rising via the sitstand policy`;鸭子 z 0.065 → 0.116 |
| 站立 | 保持 twist=0 | **7 s 稳定**:z=0.116 恒定,gz=-1.000 |
| 行走 | `robot.move {vx:0.25}` @20 Hz | **15 s 走 1.45 m**(x 0.048→1.495,均速 0.097 m/s),z 0.115–0.121,gz≈-1.000,未摔倒 |
| 健康 | `robotctl health` | `healthy`,46–48 of 50 Hz(隧道下),imu ready,电池 7.40 V(仿真) |

## 关键发现(都写进代码注释/文档了)

1. **`robot.init` 不使能策略**。`driving = intents.enabled() && bringup==Ready && ...`
   (`main.rs:2613`),而 `enabled` 默认 false(`intents.rs:277`)。
   必须**先 `robot.enable`(Start)再 `robot.init`**,且 **init 后 1 秒内**(`sitstand.unwind_s=1.0`
   → `DEFAULT_SITSTAND_RISE_S=1.0`)才会走 sitstand 起身;超窗口就退化为 Sit::Up → 站立网络。
2. **`robot.init` 单独使用会让坐着的鸭子倒**:没有策略平衡时,线性 ramp 从折叠腿拉到 home 必倒
   (上游 body_server 注释也这么说:"A biped at a static pose is not stable")。
3. **HOME 起始反而更容易倒**:直接用 `--keyframe HOME` 起步,策略接管后鸭子前倾摔倒(x 冲出去 13 cm);
   从 **SIT 走 sitstand 起身**才是设计路径。
4. **仿真重启后 daemon 会自动重连**(`RemoteIo` 每 tick 重试),但**不会重发力矩**——
   新仿真进程的 `released=False`,鸭子被 `restore()` 冻结。需要 `relax`+`init` 重新握手
   (或重启 daemon)。注意: 注意 `relax` 会让鸭子塌下去,顺序要小心。
5. **速度跟踪有差距**:命令 0.25 m/s,实测 0.097 m/s(≈39%);y 方向漂移 -0.4 m。
   原因是 `duck-body` 的 `scene.xml` 用简单位置执行器,而策略是在 **BAM 摩擦/电压模型**下训练的
   (sim-to-sim gap)。**站立/平衡不受影响**(gz 恒 -1.0),行走速度受影响。
   → 若要速度保真,用 microduck_rl 的 `scripts/infer_policy.py`(BAM M6 执行器)做排练。
6. **仿真在开发机上,运行时在板子上**:`ssh -R 7801:127.0.0.1:7801` 把开发机的仿真端口
   映射到板子的 localhost,`robotd --sim 127.0.0.1:7801` 用默认地址即可。
   实测 RTT p50 3 ms / max 10 ms,环率 46-48 Hz(健康门限 45 Hz)。
7. **viewer 与实时性**:开 MuJoCo 窗口后本机渲染会拖慢实时步进(曾落后 7.6 s);
   本次演示时无落后告警,但**做性能测量时用 `--headless`**。

## 复现命令

```bash
# Windows(本机)
cd microduck_rl
PYTHONPATH=src <repo>/k3/local-sim/.venv/Scripts/python.exe \
    -m mjlab_microduck.sim.body_server --port 7801            # 默认 SIT

# Windows(另一终端):反向隧道
cd <tools>
K3_SSH_HOST="root@<board> -p 22" ./tools/k3ssh.sh root@<board> \
    -N -R 7801:127.0.0.1:7801 -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes

# K3
cd /opt/microduck-k3/microduck
setsid nohup ./target/release/robotd --sim 127.0.0.1:7801 </dev/null >/tmp/robotd-sim.log 2>&1 &
python3 /tmp/sim-drive.py --enable --init --vx 0 --seconds 8     # 起身+站立
python3 /tmp/sim-drive.py --vx 0.25 --seconds 16                 # 行走
./target/release/robotctl health
```
