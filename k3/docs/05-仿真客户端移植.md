# 05 · 仿真客户端移植(`robotd --sim`)

> **2026-09-08 发现并完成。** 上游 v0.11.0 的 `robotd` **没有 `--sim`** —— 而 `duck-body`
> 的文档字符串和 `robotd --sim 127.0.0.1:7801` 的用法在 microduck_rl 里写得明明白白。
> 这是"数字孪生"链路的第一块缺口,本节记录定位与移植。

## 缺口定位

| 事实 | 证据 |
|---|---|
| v0.11.0(`5984efb` main)无 `--sim` | `robotd/src/main.rs` 的 `Args` 只有 `--socket/--params/--port/--fake/--no-policy/--unhealthy/--busy` + `init` 子命令 |
| `RobotIo` 只有两个实现 | `DynamixelIo`(串口,`bus.rs:244`)、`FakeIo`(`io.rs:264`) |
| `duck-control` 无 `sim` 模块 | `lib.rs` 模块表:bus/fall/imu/io/model/obs/policy/safety |
| body_server 引用的 `docs/design/simulation.md` | 该文件在 v0.11.0 中不存在 |
| **上游分支 `sim-remote-io` 有** | `git ls-remote` → `refs/heads/sim-remote-io`(`0cd676d6`),含 `duck-control/src/sim.rs`(432 行)+ `--sim` 接线 |

分支比 main 旧很多(110 文件、-24485 行:没有 policy channel、updater 重写等),**不能整支切换**。

## 移植方案(v0.11.0 + 仿真客户端)

本地分支 `k3-sim-port`(基于 `main`),4 个文件:

| 文件 | 改动 |
|---|---|
| `duck-control/src/sim.rs` | **新增**,取自 `sim-remote-io` 分支,432 行原样 |
| `duck-control/src/lib.rs` | +`pub mod sim;`(2 行) |
| `duck-control/Cargo.toml` | +`serde_json = { workspace = true }`(分支有、main 没有) |
| `robotd/src/main.rs` | +`--sim: Option<String>` 参数 + 启动分支(3 处) |

适配 main 的两处差异:
1. main 的 `RobotIo` trait 多了 `reboot(id)` → 在 `RemoteIo` 上补一个 no-op(仿真伺服没有固件可重启;
   返回 `Ok` 而非错误,免得"重启卡住的舵机"这条恢复路径在仿真里变成二次故障);
2. main 的 `control_loop` 多一个 `params_path` 参数 → 调用处按 main 签名传。

协议(与 `duck-body` 一致,`PROTOCOL = 1`):NDJSON over TCP,
`hello{protocol,joints}` / `read` / `write{targets}` / `gain{kp}` / `torque{on}` / `slow`。

## 构建验证(K3,riscv64)

```
cargo check -p duck-control -p robotd --release   → Finished (9.80s)
cargo build --release --workspace \
    --exclude mediad --exclude duck-detect --exclude pet-detect
```

途中修的依赖问题:
- `libudev-sys`(经 `padd → gilrs → gilrs-core`)需要 `libudev-dev` + `pkg-config`
  → `apt-get install -y libudev-dev pkg-config`(Bianbu 仓库有,259-1ubuntu3bb8);
- `mediad`(gstreamer)与 `duck-detect/pet-detect`(rknn)按方案裁剪。

## 用途

- **K3 版软件栈**的测试入口:`robotd --sim` 让"换脑"在无硬件时可验证(策略环、IPC、
  健康、更新器全部照跑,只是身体在 MuJoCo 里);
- 上游若合并该分支,本移植可撤;在那之前它是 K3 栈的必要补丁。
