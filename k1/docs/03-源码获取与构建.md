# 03 · 源码获取与构建(离线转储)

> K1 上 **`github.com` 不可达**(实测 000),`git clone` 失败。
> 本文件记录"从本机打包 → scp → K1 解包"的转储路径,以及构建的启动状态。

## 1. 为什么不用 `git clone`

| 通道 | 结果 |
|---|---|
| `https://github.com/pollen-robotics/microduck` | ❌ 000(连接超时 134 s 后失败) |
| `https://codeload.github.com/.../tar.gz/...` | ✅ 200 |
| `https://index.crates.io/config.json` | ✅ 200 |

`git clone` 走 `github.com`,所以**必须换路**。两条备选:

- **A(本次采用)**:本机已有 `k3-sim-port` 分支的工作树 → 打包传过去。
- B:在 K1 上用 `codeload` 下 tarball(能拿到 main,**但拿不到 `k3-sim-port` 的改动**)→ 还需单独传补丁。

A 更省事,而且一次带上了 `.git`(方便日后在板上 `git diff` / 切分支)。

## 2. 转储步骤(实测)

> **源码已备好**:[`../microduck_src/`](../microduck_src/)(22 MB,主仓 v0.11.0 + `--sim` 补丁,
> 不含 `.git`/`target`)。直接从它打包即可,不必回到 `Work_World\microduck\`。

```bash
# 本机(Git Bash):打包
cd "/c/Users/zhuxuanjia/Desktop/Work_World/Microduck 机器鸭 × 进迭时空 优秀案例/K1"
tar czf /tmp/microduck-k1-src.tar.gz microduck_src

# 传输(scp 用 -P 大写端口;沿用 yolos-box 的 SSH_ASKPASS 机制)
ASKPASS="$(mktemp)"; printf '#!/bin/sh\necho "bianbu"\n' > "$ASKPASS"; chmod +x "$ASKPASS"
SSH_ASKPASS="$ASKPASS" SSH_ASKPASS_REQUIRE=force DISPLAY=:0 \
  scp -O -o StrictHostKeyChecking=accept-new -o PreferredAuthentications=password \
      -o PubkeyAuthentication=no /tmp/microduck-k1-src.tar.gz root@<k1-ip>:/opt/microduck-k1/

# K1:解包(注意改名成 microduck,env-init/build 都按这个路径)
cd /opt/microduck-k1 && tar xzf microduck-k1-src.tar.gz && mv microduck_src microduck
```

## 4. 构建命令与状态

```bash
cd /opt/microduck-k1/microduck
export PATH="$HOME/.cargo/bin:$PATH"
setsid nohup bash -c "cargo build --release --workspace \
    --exclude mediad --exclude duck-detect --exclude pet-detect" \
    > /tmp/k1-build.log 2>&1 &
```

| 时点 | 状态 |
|---|---|
| 启动 | ✅ 进程在跑,日志进入 `Updating crates.io index` |
| 板子离线前 | 🟡 **仍在下载依赖,未进入 `Compiling`** |
| 结果 | ❓ **未知**(板子随后不可达) |

> **待办**:板子回来后在 `/tmp/k1-build.log` 里查 `grep -c "^   Compiling"`,
> 若文件已随重启丢失,重跑上面的命令即可(依赖缓存若还在,会快很多)。

## 5. 若构建失败,按这个顺序排查

1. `libudev-sys`(`padd → gilrs`)→ `apt install libudev-dev pkg-config`(**本次已装**)
2. `dbus vendored`(`configd`/`btd`)→ `--exclude configd --exclude btd`
3. `ort rc.11` 与 `libonnxruntime.so.1.18.1` 的 ABI 问题 → **这是运行期问题**,编译能过也要在 04 里验
4. 磁盘(47 G 可用)与内存(3.8 GiB)在裁剪构建下应够;若 OOM,用 `cargo build -j4`
