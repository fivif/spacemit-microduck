# 03 · 源码部署与构建

> 源码已备好:[`../../microduck/`](../../microduck/)(约 22 MB,上游 v0.11.0 + `--sim` 补丁,
> 不含 `.git`/`target`)。本文件记录把它送到板上并构建的流程。

## 1. 打包与传输

```bash
# 开发机:打包(在仓库根目录)
tar czf /tmp/microduck-k1-src.tar.gz microduck

# 传输
scp /tmp/microduck-k1-src.tar.gz root@<board>:/opt/microduck-k1/

# 板子:解包(解出来即 /opt/microduck-k1/microduck,脚本按这个路径写)
cd /opt/microduck-k1 && tar xzf microduck-k1-src.tar.gz
```

带 `.git` 的完整包也可以用(便于在板上 `git diff`),但源码树本身不含它。

## 2. 解包后的状态核对

| 项 | 值 |
|---|---|
| 路径 | `/opt/microduck-k1/microduck` |
| `duck-control/src/sim.rs` | 17 026 B / 439 行 |
| 与上游的差异 | 4 文件(`Cargo.toml`/`lib.rs`/`robotd/src/main.rs` + 新增 `sim.rs`) |
| git 依赖 | **0**(`Cargo.lock` 519 registry / 0 git 源,可离线 vendor) |

## 3. 构建

```bash
cd /opt/microduck-k1/microduck
export PATH="$HOME/.cargo/bin:$PATH"
setsid nohup bash -c "cargo build --release --workspace" \
    > /tmp/k1-build.log 2>&1 &
```

| 项 | 实测 |
|---|---|
| 耗时 | **43m39s** |
| crate | 313 |
| 产出 | `robotd` 7 319 888 B,另有 `robotctl` / `duckctl` / `duck-bench` / `mediad` 等 |

> 上表那次构建带着 `--exclude duck-detect`(`2026-09-10` 去掉)与 `--exclude mediad`
> (`2026-09-11` 撤销)。`duck-detect` 靠 `dlopen` 找运行时,编译期不需要 `librknnrt.so`;
> 运行期在 K1 上走 `src/spacemit.rs` 挂 SpaceMIT EP,没有就退回 CPU。增量重建
> `cargo build --release -p duck-detect` 实测 **35.82s**。
>
> `mediad` 也编得过了 —— 它此前断在构建上,原因**不是** riscv64 缺 GStreamer/厂商硬件编码,
> 而是板上没装 GStreamer 的 `-dev` 包(见 §4 第 2 条,`env-init.sh` 已装)。装齐后全量构建通过,
> `target/release/mediad` 可运行:USB 摄像头链路 MJPEG → UYVY → `spacemith264enc`(硬件 H.264)
> → WebRTC 出实帧。**K1 现在不裁任何 crate。**

**为什么比 K3 慢 6.5 倍**:K1 只有 3.8 GiB 内存且**无 swap**,
六个 rustc 并行(合计约 1.9 GB)时内核反复回收页缓存,load average 达 10.36。
需要更稳的墙钟时间可以用 `cargo build -j4` 降低并行度。

## 4. 若构建失败,按这个顺序排查

1. `libudev-sys`(`padd -> gilrs`)-> `apt install libudev-dev pkg-config`
2. `gstreamer-sys`(`mediad`)-> `apt install libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev libgstreamer-plugins-bad1.0-dev`
   —— `mediad` 的所有 GStreamer 绑定都在这里;这三个包装上之前,整个 workspace 都断在 `mediad` 处
3. `dbus vendored`(`configd`/`btd`)-> `--exclude configd --exclude btd`
4. `ort` 与 `libonnxruntime.so` 的版本问题 -> **这是运行期问题**,编译能过也要验(见 04)
5. 内存不足 -> `cargo build -j4`

## 5. 构建后的一键路径

```bash
# 板上(脚本先传过去,见 ../k1/README.md)
bash run-all.sh            # 环境 -> 构建 -> ORT 验证 -> robotd 冒烟 -> 联调提示
bash run-all.sh --only-ort # 只验 ONNX Runtime
```

ONNX Runtime 未通过时按 [`04-与K3差异与R1风险.md`](04-与K3差异与R1风险.md) 处理。
