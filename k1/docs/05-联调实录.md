# 05 · K1 联调实录:机器鸭换脑跑通(2026-09-09)

> **一句话**:K1 上原生编译的 `robotd`,经 SSH 反向隧道接本机 MuJoCo 数字孪生,
> 用官方 ONNX 策略完成**起身 → 站立 → 行走 → 转向**,全程未摔;
> 并部署了 Web 控制台,可用浏览器摇杆实时操控。
> **这是 K1 版的 P0 + P1 核心达成。**

## 与 K3 的对比

| 指标 | K1(8×X60) | K3(8×X100) |
|---|---|---|
| 裁剪构建 | **43m39s** | **6m42s** |
| `--fake` 空载 | **50.0 Hz / 0 missed** | 49.0 Hz / 0 missed |
| `--sim` 联调 | 46.5–48.5 Hz | 47.9 Hz |
| 满载最低 | 注意: **40.7 Hz** | 未低于 45 |
| 行走 | 1.245 m | 1.145 m |

**结论**:K1 能跑通完整链路,但**满载时余量不足**(掉到健康门限以下)—— 这是 K1 相比 K3 的第一个实测性能差距,也是 P2 真机集成要正视的点(真机还有舵机总线负载)。

## 踩坑清单

1. **源码通过打包传输部署**(见 `docs/03`)。
2. **R1 的解法就在板子上** —— `python3-spacemit-ort` 自带 `libonnxruntime.so.1.24.0+spacemit.a3`,
   不必从别处搬。
3. **构建慢的真正原因是内存,不是 CPU** —— K1 只有 3.8 GiB 且**无 swap**,
   6 个 rustc 并行时(合计 ~1.9 GB)内存压力使内核反复回收页缓存,load average 飙到 **10.36**。
   若重来可用 `cargo build -j4` 换更稳的墙钟时间。
4. **`sit_toggle` 是切换,不是"起身"** —— 连按两次就坐回去了。日志里 `sit toggle direction="sit"/"stand"` 会显示方向。
5. **已折叠的鸭子不要用 `robot.init`** —— 它会用线性 ramp 重新归位,把折叠的鸭子拖倒
   (web 控制台 `server.py` 的注释写明了这一点)。正确姿势是 `sit_toggle`。
6. **本机只能跑一个 `body_server`** —— 多个实例抢 7801,只有第一个绑上,
   后启动的"重启"看着成功其实没生效(鸭子状态不变)。清理时注意每个实例还有一个 wrapper 进程。
7. **浏览器和测试脚本会互相覆盖指令** —— `robot.move` 是 last-writer-wins,
   浏览器摇杆发的 `vx` 会和脚本发的值互相盖。调试时先关页面。
8. **`robotctl health` 默认读 `/run/robotd.sock`**,自建 socket 要传 `--robot-socket`
   (不是 `--socket`,后者是 updaterd 的)。
9. **仿真执行器是简化的** —— `duck-body` 用位置执行器,策略是在 BAM 摩擦模型下训的,
   速度跟踪只有 37–39%,**指令过猛容易摔**(实测 `vx=-0.40` 把鸭子开翻)。

## 复现命令

```bash
# Windows:启动仿真(带窗口;性能敏感时加 --headless)
cd microduck_rl
PYTHONPATH=src "<repo>/k3/local-sim/.venv/Scripts/python.exe" \
    -m mjlab_microduck.sim.body_server --port 7801 --keyframe SIT --host 0.0.0.0

# Windows:反向隧道(K1 无公网隧道,走局域网)
ssh -N -R 7801:127.0.0.1:7801 root@<board> \
    -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes

# K1
cd /opt/microduck-k1/microduck
export ORT_DYLIB_PATH=/opt/microduck-k1/ort/libonnxruntime.so
setsid nohup ./target/release/robotd --sim 127.0.0.1:7801 </dev/null >/tmp/robotd-k1-sim.log 2>&1 &
python3 /tmp/sim-drive.py --enable --init --vx 0 --seconds 12   # 起身 + 站立
python3 /tmp/sim-drive.py --vx 0.25 --seconds 14                # 行走
./target/release/robotctl --robot-socket /run/robotd.sock health

# K1:Web 控制台
cd /opt/microduck-k1/web
setsid nohup python3 server.py --port 8081 --socket /run/robotd.sock </dev/null >/tmp/k1-web.log 2>&1 &
# 浏览器打开 http://<board-ip>:8081/
```

## 结论

**K1 版的 P0 + P1 核心达成**:riscv64 原生运行时 + 官方策略 + 数字孪生闭环 + 浏览器操控。
「用 SpacemiT K1 作为机器鸭大脑」在**软件层面成立**。
剩下的:真机硬件(舵机总线/供电/装机)——需硬件;以及满载环率余量的优化。
