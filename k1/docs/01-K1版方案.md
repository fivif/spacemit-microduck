# 01 · K1 版方案

> **一句话**:把 K3 已跑通的换脑方案平移到 **SpacemiT K1(MUSE-Pi-Pro)**,代码零改动。
> K3 立"算力标杆",K1 给"能装进鸭子的落地形态"。
> 上游参考:[`../../K3/docs/04-K1版前瞻.md`](../../K3/docs/04-K1版前瞻.md)(立项时的差异预判)。

## 1. 为什么还要 K1

| | K3 | K1 |
|---|---|---|
| 角色 | **算力标杆** —— 证明 RISC-V 跑得动机器人运行时 | **落地形态** —— 真机换脑的实际载体 |
| 板卡 | K3 Pico-ITX(2.5" SBC) | **MUSE-Pi-Pro**(体积/功耗更贴近 800 g 的鸭子) |
| 叙事 | 技术高度 | 可落地的集成路径 |

两条线共同前提:**仿真与训练不上板**;换脑 = 把 `robotd` 50 Hz 控制环 + 策略 + 舵机总线
在 RISC-V 上原生编译运行。

## 2. 平移依据:为什么"代码零改动"

策略是 **512-256-128 的 MLP**(输入 61 维、输出 14 维、50 Hz),计算量极小;
K1 与 K3 的差异**全部落在运行性能上,不落在编译路径上**:

| K1 与 K3 的差异 | 影响编译? | 影响运行? |
|---|---|---|
| CPU 微架构 X60 vs X100 |  同一个 `riscv64gc` target |  只是慢一档 |
| AI 算力 2 TOPS vs 60 TOPS |  两边都走 CPU EP |  策略 MLP 用不上 |
| 板卡形态 MUSE vs Pico-ITX |  与软件无关 | 否 |
| `libonnxruntime.so` 版本 | 否 | 注意: **唯一真风险(见 04)** |

## 4. 验收标准(复刻 K3 的 P0)

| 步 | 内容 |
|---|---|
| 1 | K1 上 rustup + `riscv64gc-unknown-linux-gnu` target |
| 2 | 裁剪构建产出 `robotd` 等二进制 |
| 3 | **`ort` 吃上 K1 的 `libonnxruntime.so`(R1,见 04)** |
| 4 | `robotd --sim` 接本地 MuJoCo 仿真 |
| 5 | 复刻:坐姿起身 → 站立 → 行走,记录环率与位移 |
| 6 | 与 K3 做同场景算力/环率对比 |

## 5. 与 K3 的预期差距

- **单核**:X100 SPECint2006 **9.5** vs X60 **3.5** → 约 2.7×;但 50 Hz 环 + MLP 本就占不满一个核,K3 实测 46–48 of 50 Hz,**K1 预计仍富余**。
- **内存**:K1 实测 **3.8 GiB**(4 GB 档),裁剪构建足够。
- **实时核**:K3 有 RCPU 600 MHz(直挂 CAN-FD/TSN),**K1 没有** —— 舵机总线若要求硬实时,K1 需靠内核调度,这是 P2 真机集成的评估点。
